# Pi-2000 0.1.0-alpha.6

Alpha 6 adds Pi-IPTV, Pi-Vault, a personal desktop and workspace recovery, with
security and maintenance improvements since Alpha 5. The Windows 2000-inspired
Python/aiohttp and plain JavaScript desktop remains the foundation.

## Changes

- **Pi-IPTV:** private M3U/M3U8 URLs, file imports and Xtream credentials;
  country/group search, live TV, movies, series/episodes, favorites, viewing
  positions, XMLTV and provider-supported archives. HLS, TS and native media use
  authenticated opaque URLs. Optional FFmpeg audio/video conversion is isolated.
  Four-second TS startup buffering and less aggressive live catch-up absorb
  network jitter; HLS quality changes preserve buffered video. No subscription
  or channel rights are supplied.
- **Pi-Vault:** client-encrypted private lists and entries, separate list/content
  passphrases, per-entry unlock, automatic locking, recovery and encrypted
  import/export. Password/recovery changes rotate data keys. See the
  [Pi-Vault trust boundaries](https://github.com/xhonken/Pi-2000/blob/v0.1.0-alpha.6/docs/VAULT.md).
- **Personal desktop:** app icon selection, naming/removal, Start pinning,
  Windows-style selection/drag/context menus, sorting and conflict-safe settings.
- **Workspace recovery:** saved window layout and supported editor, Arduino,
  drawing and calculator drafts return after login/restart. Pi-Vault stays locked,
  IPTV does not autoplay, and lost processes are not recreated from checkpoints.
- **Security fixes:** Browser log symlink handling, descriptor-based privileged
  backups, phpMyAdmin request revocation, bounded requests/logins, hardened
  headers and a minimum reviewed Browser-engine version. Browser cold startup
  now binds the account identity before starting its runtime.
- **Maintenance:** guarded OS-administrator restore and encrypted backup export,
  installed/running worker status, idle activation, common deployment inventories
  and reproducible local/CI checks. Existing Pi++, Pi-Arduino, database,
  SSH and graphical tools remain included.

## Download and installation

Target: **Raspberry Pi OS 64-bit / Debian 13 (Trixie), arm64, Python 3.13**.
Debian 12, 32-bit systems and Intel/AMD are not supported by this package.

Download `pi2000web_0.1.0.alpha.6-1_arm64.deb` and `SHA256SUMS` into the same
directory:

```sh
sha256sum --check SHA256SUMS
sudo apt install ./pi2000web_0.1.0.alpha.6-1_arm64.deb
sudo pi2000web doctor
```

The internal Debian version is `0.1.0~alpha.6-1`; GitHub uses a dot in the download
filename. The package supplies pinned Python runtimes and Arduino CLI. APT installs
native dependencies, including FFmpeg; Arduino board packages/libraries are
downloaded separately per account. No credentials or private installation data
are included. See the [Debian installation guide](https://github.com/xhonken/Pi-2000/blob/v0.1.0-alpha.6/docs/DEB-INSTALLATION.md).

## Upgrade notes

1. Back up and finish active work, database operations and Arduino jobs. Disconnect
   Serial Monitor/Plotter before planned worker activation.
2. On a package-managed host, install the new package with APT. The upgrade requires
   a verified local backup and preserves private data. API/PHP services restart;
   active sessions and Arduino workers can retain their previous code.
3. Inspect `sudo pi2000web workers status`; activate updated workers once idle using the
   [maintenance guide](https://github.com/xhonken/Pi-2000/blob/v0.1.0-alpha.6/docs/MAINTENANCE.md).
   Run `sudo pi2000web doctor` and reload the desktop afterwards.
4. Source-managed hosts use the [source updater](https://github.com/xhonken/Pi-2000/blob/v0.1.0-alpha.6/docs/INSTALLATION.md).
   The package refuses to overwrite an unmanaged source installation. Do not mix
   the two installation methods or downgrade against migrated live data.

The Browser app requires Chromium **153.0.8010.52 or newer** under the dated
security policy. A distribution with an older engine will leave Browser paused
until an OS update supplies a supported engine. This does not disable IPTV in
your client browser. This floor is not a guarantee against future vulnerabilities.

## Validation and remaining limits

Release preparation passed **184 backend tests, 26 ordinary browser suites and
2 geometry suites**, including private-account boundaries, Pi-Vault rotation, recovery, generated
HLS/TS/MP4 audio/video and sandboxed compatibility conversion. A controlled TS
test with a 2.5-second network outage improved from two buffering stops and one
catch-up seek to zero of each. Installed Pi 5 checks verified HTTPS, PAM, public
playlist import and external HLS/MP4 decoding; the operator also reported smooth
audio/video and several successful channel changes after the buffering fix.

The release package is checked for metadata, clean build identity, exact deployed
content, dependencies and checksums. The new README screenshot uses an isolated
demo with generated test media, not production accounts or a subscription.

**Fresh installation of this exact package on a reimaged Pi 4 remains pending.**
Earlier physical package tests and installed Pi 5 feature checks do not replace
that acceptance. Physical power-loss recovery and independent security/crypto
review remain separate work. Workspace recovery saves supported application
state, not running processes or every third-party application.

IPTV playback still depends on provider availability, bandwidth and browser
codecs. DRM, web-page/UDP/RTSP/LAN sources and FFmpeg conversion of HLS are not
supported; archive playback requires provider support. See the
[IPTV guide](https://github.com/xhonken/Pi-2000/blob/v0.1.0-alpha.6/docs/IPTV.md) and
[security boundaries](https://github.com/xhonken/Pi-2000/blob/v0.1.0-alpha.6/docs/SECURITY.md).
This is an Alpha test release, not a certification of production security.
