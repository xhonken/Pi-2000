# Pi-2000 0.2.0-alpha.8

Alpha 8 starts an independent Pi-2000 data line. **A fresh installation is
required. Alpha 5, 6 and 7 cannot be upgraded to this version.** Keep the previous
installation and its backups on a separate system. This is a testing prerelease.

## Changes

- Pi-2000 identifiers throughout the maintained source: service/task names,
  environment variables, session cookie, browser storage, JavaScript namespaces,
  CSS, custom events, drag types, tests and package setup.
- Main stylesheet renamed to `dist/pi2000-ui.css`.
- Removed the earlier namespace migrator, browser-wide settings import and
  initial database conversions. Old reviews, provenance and releases remain in
  their immutable Git snapshots.
- Installers reject earlier packages and unmarked installations before adoption.
  Runtime startup rejects earlier SQLite databases without changing them.
  System backups use format 3 and refuse earlier formats before extraction.
- Application features and classic appearance retained, including Pi-IPTV,
  Pi-Vault, Pi-Arduino, Pi++, private files, SSH, MariaDB and workspace recovery.
- GitHub CI now includes the hidden disposable UI artifact directory in uploads.

## Installation

Target: arm64 Raspberry Pi OS based on Debian 13 (Trixie), Python 3.13.
Download `pi2000web_0.2.0.alpha.8-1_arm64.deb` and `SHA256SUMS` from this release.
The internal Debian version is `0.2.0~alpha.8-1`; GitHub normalizes the filename.

On a fresh, dedicated system:

```sh
sha256sum --check SHA256SUMS
sudo apt install ./pi2000web_0.2.0.alpha.8-1_arm64.deb
sudo pi2000web doctor
```

Follow the [package guide](https://github.com/xhonken/Pi-2000/blob/v0.2.0-alpha.8/docs/DEB-INSTALLATION.md)
and [installation boundary](https://github.com/xhonken/Pi-2000/blob/v0.2.0-alpha.8/docs/SYSTEM-NAMES.md).
Do not bypass the version guard, forge installation markers or copy an earlier
private state directory into Alpha 8. Export ordinary documents through the old
version and import the files you need into new accounts. There is no automatic
account/settings/system-backup conversion.

## Validation and limits

Validation covers 190 backend tests, all 27 ordinary browser UI suites, two
geometry suites, two real MariaDB UI suites and the phpMyAdmin UI suite. It includes
fresh-data/restart checks and isolated package pre-install fixtures.
Rejection tests cover Alpha 5/6/7 versions, source installations, old databases
and backups, including verification that rejected data remains unchanged.
Package identity, manifests, checksums and the absence of the former namespace
are checked before publication. The screenshot uses disposable demonstration
accounts and locally generated TV media.

**A complete installation of this exact package on a freshly imaged Pi 4 remains
pending.** Existing Pi 5 acceptance belongs to the earlier data line; publication
does not install Alpha 8 over that system. Physical reboot/power-loss recovery,
ESP32 upload/display tests and an independent security audit remain separate.
Browser still requires the documented Chromium security floor; a distribution
engine below it is paused. IPTV availability and codecs depend on the provider.

Published Alpha 7 and earlier tags/assets are unchanged. Git history preserves
historic names; the new release's maintained source uses Pi-2000 identifiers.
