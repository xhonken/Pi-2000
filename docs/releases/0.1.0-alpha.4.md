# Pi-2000Web 0.1.0-alpha.4

Alpha 4 adds Linux-PAM authentication, private Linux identities and administrator Local Terminal, together with an arm64 Debian installer and desktop reliability improvements.

## Accounts and passwords

- Each managed web account has its own Linux identity and private home. PAM authenticates migrated accounts; the old application password verifier is removed after migration.
- The installation creator is protected by stable identity. Debian setup asks for its username and confirmed password.
- Administrators receive Local Terminal under their own identity, without automatic sudo. Ordinary managed users have no login shell. Managed identities are excluded from the host SSH listener; Local Terminal uses a private loopback listener.
- Account activation, exact-name deletion confirmation, interrupted-provisioning recovery and session revocation following external password changes are supported.
- Existing Linux identities can be linked explicitly by an OS administrator. Their passwords, homes and permissions are preserved; password changes for linked accounts use `passwd` locally.
- Initial MariaDB provisioning creates a private creator connection. Later web/Linux password changes do not change its separate SQL credentials.

Read [system account operations](https://github.com/xhonken/Pi-2000/blob/v0.1.0-alpha.4/docs/SYSTEM-ACCOUNTS.md) before migration or recovery.

## Installer and desktop

The release includes `pi2000web_0.1.0~alpha.4-12_arm64.deb` and its SHA-256 checksum for **Raspberry Pi OS 64-bit / Debian 13 (Trixie), arm64, Python 3.13**. It includes pinned Python runtimes and uses APT for native dependencies. Debian 12 and 32-bit systems are not supported by this build.

The installer provides terminal setup dialogs, private local MariaDB provisioning, isolated HTTPS configuration and a verified backup before upgrades. It preserves user data on package removal. A package-managed installation must be updated through APT; the package does not overwrite a legacy source installation.

Other changes since Alpha 3:

- Dedicated Local Terminal desktop icon for administrators.
- More reliable native file/folder upload pickers from the desktop and Files.
- Unsaved API request and Git editing protection; SQL drafts saved before logoff.
- Installed version, source revision and build identity in Help → About.
- Earlier phpMyAdmin deprecation filtering for page and AJAX rendering while retaining actionable warnings.
- Browser starts at 1280 × 720 and allows up to three minutes for cold SD-card initialization. The 2 GB profile retains a 1024 MiB hard limit, 896 MiB high threshold and 128 MiB swap limit.
- Broader backup/staging-restore and real HTTPS Git remote test coverage.

## Upgrade

1. Back up private data and finish database operations and live terminal/Browser jobs.
2. Follow the [source installation and update guide](https://github.com/xhonken/Pi-2000/blob/v0.1.0-alpha.4/docs/INSTALLATION.md) or [Debian package guide](https://github.com/xhonken/Pi-2000/blob/v0.1.0-alpha.4/docs/DEB-INSTALLATION.md), according to how the host was installed.
3. Restart the session worker after finishing jobs so the new account policy is active; run doctor and reload the desktop.
4. Legacy accounts migrate on their next successful password login. Existing OS accounts are never linked merely because their names match. Review password policy and linked-account handling in the system account guide.

Do not downgrade against migrated live data. Older backups can contain legacy password verifiers; protect them accordingly.

## Validation and remaining work

- Release preparation reran all **102 backend tests successfully**. Installed PAM/broker files on the existing Pi 5 match the tested implementation, and the account broker, private SSH listener, API and session worker are active.
- The preceding implementation validation on Pi 5 covered real HTTPS/PAM login, per-user Local Terminal, role isolation, password changes, session revocation, creator protection and disposable account cleanup. Root-only backup and staging restore included managed homes/registry and excluded linked OS credentials.
- Earlier Debian candidates passed physical Pi 4 installation, reboot, upgrade, remove/purge/reinstall, data preservation, terminal setup and Browser/phpMyAdmin/Git/upload tests. Those tests predate the final PAM account migration.
- **Fresh installation of the final PAM-enabled package on a reimaged Pi 4 remains pending.** The release package is built and inspected; the older Pi 4 results must not be treated as acceptance of this final installer.
- Full OS-account restore requires manual UID/home reconciliation. Backups exclude symlinks/special files and do not automatically restore executable modes or original ownership. Linked OS homes and password records are not included.
- This is Alpha software. The 2 GB profile has functional coverage, not long-duration or multi-user load validation. Package checks and current service status are not a repeat of privileged end-to-end production tests.
