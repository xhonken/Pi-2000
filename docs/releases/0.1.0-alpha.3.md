# Pi-2000Web 0.1.0-alpha.3

This Alpha expands Pi-2000 into a database and development desktop. MariaDB Manager now embeds upstream phpMyAdmin with the Pi-2000 Windows 2000 appearance and private saved local/remote connections.

## Changes

- Integrated phpMyAdmin: server/database/table navigation, SQL, structure, rows, search, account/grant administration and import/export, subject to the connected database account's permissions.
- Private saved MariaDB connections with encrypted credentials, verified TLS/custom CA support and visible connection errors.
- Retained native SQL workspace with closable scrolling query tabs, query management, separate per-query results and direct insert/edit/delete forms. Blank auto-increment IDs and timestamp defaults are handled explicitly.
- Guided SELECT/JOIN builder, database/user/schema administration dialogs, filtering/sorting, relation inspection and bounded export/restore jobs.
- Git Projects with private sandboxed workspaces, local status/diff/staging/commits, branches and HTTPS remote controls.
- API Tester with private encrypted saved requests and response inspection.
- Code Editor syntax diagnostics for Python, JavaScript and JSON.
- Browser memory admission checks, clearer memory-limit failure/reconnect status and warnings.
- Start menu Search button text now fits at larger font sizes.

## Upgrade

Target: Raspberry Pi 5, 64-bit Debian 13 / compatible Raspberry Pi OS environment, Python 3.13 and PHP 8.4. A fresh installation on a newly imaged physical Pi has not been independently retested for this release.

Back up before upgrading. Finish database operations first: the updater restarts the API and active database sessions are not restored.

    git pull --ff-only
    sudo ./scripts/update.sh
    sudo ./scripts/doctor.sh

The updater installs distribution phpMyAdmin/PHP packages and the dedicated pi2000-phpmyadmin service. It preserves the previous phpMyAdmin configuration as a root-only backup before installing the integration configuration. The API receives access to the dedicated PHP Unix socket; PHP does not receive access to the API/worker group or private platform state.

Reload the desktop after upgrading. Open MariaDB Manager from Start; close a restored old Manager window if necessary. Existing SQL drafts remain under File → Saved SQL Workspace.

Ordinary updates preserve the persistent SSH/Browser worker. To activate worker changes from earlier commits, finish live SSH/Browser jobs and schedule an update with --restart-sessions. That option ends those jobs; saved profiles remain.

## Validation

- All 83 backend unittests passed for this release.
- Native MariaDB UI regressions passed for connections, saved workspaces, direct row operations, query management and guided joins.
- Integrated phpMyAdmin tested on the installed HTTPS desktop with a temporary Pi account and disposable MariaDB: SQL create/browse, direct insert with auto ID/timestamp, SQL download/upload, protected source paths, anonymous rejection and disconnect.
- Classic desktop UI, accessibility and English UI regressions passed. Search layout checked at 13px and 18px.
- Installed HTTPS assets, API sources, phpMyAdmin integration files, service health and platform SQLite integrity verified by doctor.

## Known limitations

- This remains an Alpha; data/API compatibility is not guaranteed.
- Optional phpMyAdmin configuration-storage features (persistent bookmarks, tracking, central columns and designer metadata) require setup on an authorized database. No shared privileged platform account is provided.
- Twig dependency deprecation notices can still appear on some phpMyAdmin pages. The user has reported remaining occurrences after the initial filter; this is not claimed fully fixed.
- Integrated phpMyAdmin imports are limited to 64 MiB, responses to 128 MiB and PHP execution to five minutes; gateway requests are serialized to bound memory.
- Native export/restore, Git workspaces and API Tester have their own documented quotas and limits.
- Git remote controls exist, but real external push/pull round trips were not part of the development-tool UI validation.
- A fresh physical-Pi installation and full disaster recovery remain separate validation work.

See docs/PHPMYADMIN.md, docs/MARIADB-MANAGER.md and docs/DEVELOPMENT-TOOLS.md for operational details.
